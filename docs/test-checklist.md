# 测试清单

本文档用于手动验证当前项目的核心流程，覆盖用户体系、多会话、消息持久化、Redis 缓存和历史上下文恢复。

## 用户模块

- [ ] 注册成功：使用新账号调用注册接口，返回成功结果。
- [ ] 重复账号注册失败：使用已存在账号再次注册，返回重复注册错误。
- [ ] 登录成功并返回 token：使用正确账号密码登录，响应中包含 token 和用户信息。
- [ ] 错误密码登录失败：使用错误密码登录，返回登录失败错误。
- [ ] 不带 token 访问 `/api/user/me` 失败：请求被拦截，返回未登录或无权限错误。
- [ ] 带 token 访问 `/api/user/me` 成功：返回当前登录用户信息。

## 会话模块

- [ ] 新建会话：调用新建会话接口后返回新的 `sessionId`。
- [ ] 查询会话列表：可查询到当前用户的会话列表。
- [ ] 重命名会话：修改会话标题后再次查询列表，标题已更新。
- [ ] 删除会话：删除会话后接口返回成功。
- [ ] 用户 A 不能访问用户 B 的会话：A 使用 B 的 `sessionId` 查询、修改、删除时应返回无权限错误。
- [ ] 删除后的会话不出现在列表中：删除后再次查询列表，已删除会话不再返回。

## 消息模块

- [ ] 发送消息后数据库生成 user 消息：发送一条消息后，`chat_message` 中新增一条 `role = user` 记录。
- [ ] AI 回复完成后数据库生成 assistant 消息：流式回复完成后，`chat_message` 中新增一条 `role = assistant` 记录。
- [ ] 刷新页面后能加载历史消息：刷新前端页面后，当前会话历史消息仍可展示。
- [ ] 切换会话后消息不串：不同会话之间各自显示自己的消息记录。

## AI 聊天模块

- [ ] `POST /api/ai/chat/stream` 可流式返回：响应头为 `text/event-stream`，客户端可逐段接收内容。
- [ ] 同一会话能延续上下文：同一个 `sessionId` 下连续提问，AI 能参考上文回答。
- [ ] 不同会话上下文隔离：切换到新的 `sessionId` 后，AI 不应引用其他会话内容。
- [ ] 不同用户上下文隔离：不同用户在各自账号下聊天，AI 不应混用上下文。
- [ ] 历史会话重新打开后能参考最近上下文：关闭或切换后重新进入旧会话，AI 能参考最近若干条历史消息继续对话。

## Redis 模块

- [ ] 登录后 Redis 出现 `login:user:{userId}`：登录成功后检查 Redis 中存在该 key。
- [ ] 查询会话列表后 Redis 出现 `chat:sessions:{userId}`：调用会话列表接口后检查 Redis 中存在该 key。
- [ ] 新建、重命名、删除、发送消息后会话列表缓存失效：执行对应操作后，旧的 `chat:sessions:{userId}` 被删除或重新生成。
- [ ] Redis 未命中时能回退 MySQL：手动删除相关 key 后再次请求，接口仍能返回正确数据并重新写入缓存。

## 前端模块

- [ ] 未登录显示登录页：首次进入页面且本地无 token 时展示登录注册面板。
- [ ] 登录后显示聊天页面：登录成功后进入主聊天界面。
- [ ] 刷新页面后恢复登录态：页面刷新后仍能保持登录状态。
- [ ] 左侧会话列表正常显示：会话列表可正常加载并展示标题、时间等信息。
- [ ] 新建、切换、重命名、删除会话正常：左侧会话操作链路完整可用。
- [ ] 发送消息使用当前会话：在当前选中的会话内发送消息，消息不会错误写入其他会话。
- [ ] 停止生成可用：生成中点击停止后，前端可结束本次生成流程且页面状态恢复正常。
